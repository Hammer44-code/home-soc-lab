# Detection: OS Credential Dumping — Security Account Manager (SAM)

> **Status: validated 2026-06-10.** Both searches fired end-to-end against ART `T1003.002-1` (`reg save`), `-3` (`esentutl /vss`), and `-8` (`reg export`) on soc-victim, in the same Defender-off session that validated [T1562.001](T1562.001-impair-defenses.md). The **secondary** burst correctly flagged the `reg save`/`reg export` hive trio as **`crackable_set=yes`** and, as a bonus, classified a `SYSTEM+SECURITY` (no-SAM) pair as **`crackable_set=no`** — proving the logic requires SAM+SYSTEM specifically, not merely any two hives. The Sample Event below is a real captured EID 1. See Tuning Notes for the full findings.

## MITRE ATT&CK

- **Tactic:** Credential Access (TA0006)
- **Technique:** T1003 — OS Credential Dumping
- **Sub-technique:** T1003.002 — Security Account Manager (SAM)

The companion sub-technique [T1003.001](T1003.001-lsass-access.md) (LSASS memory) targets the *cached, live* credentials of logged-on users. This one targets the *on-disk* local account password hashes stored in the **SAM** registry hive — decryptable only with the boot key held in the **SYSTEM** hive, which is why adversaries grab both.

## Severity

**High.** Dumping the SAM yields the NTLM hashes of every **local** account on the host — usable for offline cracking or, directly, for pass-the-hash lateral movement. There is **essentially no benign reason** for a process to copy the SAM/SYSTEM/SECURITY hives off a running system: Windows holds these files under an exclusive lock precisely so they cannot be casually read, and the *entire point* of the techniques below (`reg save`, `esentutl /vss`, shadow-copy reads) is to bypass that lock. So — like [T1070.001](T1070.001-clear-event-logs.md) log-clearing — the technique is a **sharp single signature**: the command shape *is* the malice, no scoring required. The one nuance that adds confidence is the **hive set**: SAM alone gives hashes you cannot decrypt without the SYSTEM boot key, so an adversary who grabs **SAM *and* SYSTEM** in one window has assembled the full crackable set — a meaningful escalation the secondary search surfaces.

## Detection Logic

The SAM file is locked while Windows runs, so there is **no Sysmon "file read" event** to anchor on (Sysmon has no read EID; EID 11 is file *create*). That locked-file reality is the detection's gift: every method that works has to use one of a small set of **lock-bypassing tools**, each with a sharp command-line signature on **Sysmon EID 1**:

| Method | Tool | Signature | ART test |
|---|---|---|---|
| Registry hive save | `reg.exe` | `reg save HKLM\sam …` / `reg export HKLM\sam …` | 1, 8 |
| VSS file copy | `esentutl.exe` | `esentutl /y /vss …\config\SAM /d …` | 3 |
| Shadow-copy read | `certutil.exe` / direct file copy | reads `…HarddiskVolumeShadowCopyN\…\config\SAM` (CVE-2021-36934, HiveNightmare) | 5, 6 |

### Primary — SAM-dump command (Sysmon EID 1, sharp classifier)

```spl
index=endpoint sourcetype="WinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
(CommandLine="*sam*" OR CommandLine="*system*" OR CommandLine="*security*"
 OR CommandLine="*esentutl*" OR CommandLine="*HarddiskVolumeShadowCopy*" OR CommandLine="*\\config\\*")
| eval method=case(
    match(Image,"(?i)\\\\reg\.exe$") AND match(CommandLine,"(?i)\s(save|export)\b") AND match(CommandLine,"(?i)\bhk(lm|ey_local_machine)\\\\(sam|system|security)\b"),
        "reg "+if(match(CommandLine,"(?i)\ssave\b"),"save","export")+" of a registry hive",
    match(Image,"(?i)\\\\esentutl\.exe$") AND match(CommandLine,"(?i)/vss") AND match(CommandLine,"(?i)(\\\\config\\\\(SAM|SYSTEM|SECURITY)|\bSAM\b)"),
        "esentutl VSS hive copy",
    match(Image,"(?i)\\\\certutil\.exe$") AND match(CommandLine,"(?i)HarddiskVolumeShadowCopy") AND match(CommandLine,"(?i)(SAM|SYSTEM|SECURITY)"),
        "certutil shadow-copy hive read (HiveNightmare)",
    match(CommandLine,"(?i)HarddiskVolumeShadowCopy.*\\\\config\\\\(SAM|SYSTEM|SECURITY)"),
        "shadow-copy hive read (HiveNightmare)"
  )
| where isnotnull(method)
| eval hive=case(
    match(CommandLine,"(?i)\bsam\b"),"SAM",
    match(CommandLine,"(?i)\bsystem\b"),"SYSTEM",
    match(CommandLine,"(?i)\bsecurity\b"),"SECURITY",
    1=1,"?")
| eval acct=coalesce(mvindex(mvfilter(User!="NOT_TRANSLATED"),0), User)
| table _time host acct method hive Image ParentImage CommandLine
| sort - _time
```

### Secondary — full-hive-set burst (the SAM+SYSTEM escalation)

```spl
index=endpoint sourcetype="WinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
(CommandLine="*sam*" OR CommandLine="*system*" OR CommandLine="*security*"
 OR CommandLine="*esentutl*" OR CommandLine="*HarddiskVolumeShadowCopy*" OR CommandLine="*\\config\\*")
| eval method=case(
    match(Image,"(?i)\\\\reg\.exe$") AND match(CommandLine,"(?i)\s(save|export)\b") AND match(CommandLine,"(?i)\bhk(lm|ey_local_machine)\\\\(sam|system|security)\b"), "reg hive dump",
    match(Image,"(?i)\\\\esentutl\.exe$") AND match(CommandLine,"(?i)/vss"), "esentutl VSS copy",
    match(CommandLine,"(?i)HarddiskVolumeShadowCopy.*\\\\config\\\\(SAM|SYSTEM|SECURITY)"), "shadow-copy read"
  )
| where isnotnull(method)
| eval hive=case(match(CommandLine,"(?i)\bsam\b"),"SAM", match(CommandLine,"(?i)\bsystem\b"),"SYSTEM", match(CommandLine,"(?i)\bsecurity\b"),"SECURITY", 1=1,"?")
| eval acct=coalesce(mvindex(mvfilter(User!="NOT_TRANSLATED"),0), User)
| bin _time span=5m
| stats values(hive) as hives dc(hive) as distinct_hives values(method) as methods values(CommandLine) as commands min(_time) as first_seen by host acct _time
| eval crackable_set=if(match(mvjoin(hives,","),"(?i)SAM") AND match(mvjoin(hives,","),"(?i)SYSTEM"), "yes — SAM+SYSTEM grabbed together", "no")
| where distinct_hives >= 2
| table _time host acct distinct_hives hives crackable_set methods commands
| sort - _time
```

### What each piece does

**Primary (EID 1):**

- **Sharp positive classifier + `| where isnotnull(method)`** — the same discipline as the [T1070.001 secondary](T1070.001-clear-event-logs.md). The leading `CommandLine="*…*"` filters are *deliberately loose* (the words `system`/`security`/`config` appear in countless benign command lines), so the `match()` block does the real work and the `isnotnull(method)` drops everything that does not match a real SAM-dump shape. Without that gate, `*system*` alone would scoop up half the index.
- **Binary off `Image`, hive/verb off `CommandLine`** ([§3](../notes/splunk-spl-cheatsheet.md), T1087 fix #1). `reg.exe`/`esentutl.exe`/`certutil.exe` matched on `Image`; the `save`/`export`/`/vss` verbs and `HKLM\sam` targets on `CommandLine`.
- **`\bhk(lm|ey_local_machine)\\(sam|system|security)\b` anchor** — `reg save` is benign for *application* keys (installers and admins back up `HKLM\SOFTWARE\Vendor` routinely). The malice is specifically saving the **SAM/SYSTEM/SECURITY** hives. Anchoring on `HKLM\sam` (and the long form `HKEY_LOCAL_MACHINE\sam`) keeps benign `reg save` out — the [§3 "anchor on the specific thing, not the binary"](../notes/splunk-spl-cheatsheet.md) discipline.
- **`hive`** records which hive *this* event grabbed. Because `reg save HKLM\sam`, `reg save HKLM\system`, `reg save HKLM\security` are **three separate EID 1 events**, each row carries one hive — the *set* is reconstructed by the secondary.
- **`acct` dedup** — multivalued-`User` coalesce ([T1087 fix #2](T1087-account-discovery.md)).

**Secondary (burst — the SAM+SYSTEM escalation):**

- This is the [T1087/T1082 burst-correlation idiom](T1087-account-discovery.md) repurposed. Where T1087 counted *distinct discovery commands*, this counts **distinct hives dumped** by the same account in a 5-minute `bin`. The insight is credential-specific: **SAM hashes are useless without the SYSTEM boot key.** A dump of SAM *and* SYSTEM (`crackable_set=yes`) means the adversary has the complete, offline-crackable set — strictly higher confidence and higher severity than a lone SAM grab.
- `distinct_hives >= 2` is the alert threshold; `crackable_set` specifically flags the SAM+SYSTEM pairing (the cryptographically meaningful one) versus, say, SAM+SECURITY.
- `mvjoin(hives,",")` then `match()` — `hives` is multivalued from `values()`, so it is flattened to a string before the membership test (cleaner than `mvfind` here).

## Why This Works

The detection rides on a structural fact the adversary cannot avoid: **the SAM hive is exclusively locked by the kernel while Windows runs.** A plain `copy C:\Windows\System32\config\SAM` fails with a sharing violation. So every working extraction method must reach *around* the lock — through the registry API (`reg save`), through the Volume Shadow Copy Service (`esentutl /vss`, or reading a `HarddiskVolumeShadowCopy` path), or through a backup-privilege trick. Each of those leaves a **distinctive, rarely-benign command line** on Sysmon EID 1. There is no "quietly read the SAM with ordinary file I/O" path — the OS design that protects the hive is exactly what forces the adversary into a noisy, signature-bearing tool.

And, as with every detection in this lab, the Universal Forwarder has already shipped that EID 1 off-host before the dumped hive file is even finished writing — so even if the adversary deletes `%temp%\sam` afterward, the *evidence that they made it* is already on the indexer.

This pairs naturally with [T1562.001](T1562.001-impair-defenses.md): real-time protection will block or quarantine a `reg save HKLM\sam` on a default endpoint (Defender flags hive-dump behaviour), which is *why* the adversary disables Defender first — making the two techniques a single observed sequence (impair → dump) in the same Defender-off window.

## Tuning Notes

**Pre-flight calibration:** EID 1 is the lab workhorse — confirmed flowing throughout. The only "is the data there" risk is whether the **shadow-copy tests (5/6)** have a Volume Shadow Copy to read; if none exists they no-op. The `reg save` (1) and `esentutl /vss` (3) tests are self-contained and the reliable validators — lead with those.

**Validation findings (2026-06-10) — what the live run taught us:**

- **The detection catches the *attempt*, not the *outcome* — proven twice.** `esentutl /y /vss …\config\SAM` errored out with `Operation terminated with error -1 (JET_wrnNyi, Function Not Yet Implemented)` — the VSS copy mode is **not fully implemented on this Win10 22H2 build** (a real, documentable quirk; the copy never completed). And `reg export HKLM\security` returned `Access is denied`. **Both still produced a clean EID 1** with the full command line, so both were classified and alerted. There is no "the dump failed so we didn't see it" gap — the process spawns with its intent-bearing command line *before* it can fail. Same principle the [T1562.001](T1562.001-impair-defenses.md) `sc.exe stop WinDefend` (denied) demonstrated in the same session.
- **`reg save` got SECURITY; `reg export` was denied on it — a real method distinction.** `reg save` (test 1) succeeded on all three hives because it uses **backup semantics (`SeBackupPrivilege`)**, which bypasses ACLs. `reg export` (test 8) uses **normal read ACLs**, and the **SECURITY hive denies read to Administrators** (only `SYSTEM` can read it) → `Access is denied` on `HKLM\security`. So `reg save` is the stronger attacker tool (full crackable set incl. SECURITY); `reg export` is the weaker variant. Both still trip the classifier (the `save|export` alternation), and the denied SECURITY export still generated its EID 1.
- **`esentutl` path used forward slashes — the bare-`SAM` fallback earned its place.** The captured command line was `esentutl.exe /y /vss C:\Windows/system32/config/SAM /d C:\Users\analyst\AppData\Local\Temp/SAM` (note the **forward slashes** in `Windows/system32/config/SAM`). The classifier's `\\config\\SAM` (backslash) branch would *not* have matched this — but the **`|\bSAM\b` fallback** did (the destination `Temp/SAM` token), so the event classified correctly. Concrete proof the alternation fallback was worth including ([§3 field-shape-assumption](../notes/splunk-spl-cheatsheet.md) discipline).
- **`ParentImage` is `cmd.exe`, not `powershell.exe`.** The T1003.002 atomics are **cmd-based** (`command_type: command_prompt`), so each `reg.exe`/`esentutl.exe` was parented by `cmd.exe`, and the **`ParentCommandLine` carries the whole chained trio**: `"cmd.exe" /c reg save HKLM\sam %temp%\sam & reg save HKLM\system %temp%\system & reg save HKLM\security %temp%\security`. So every child event shows, in its parent line, that all three hives were targeted in one shot — the crackable set is visible even from a single row. The [§10 "ART parents under powershell"](../notes/splunk-spl-cheatsheet.md) caveat does **not** apply to these cmd-based atomics.
- **The secondary's `crackable_set=no` row is the bonus discriminator.** A 5-minute bin that contained only `SYSTEM`+`SECURITY` exports (no SAM) correctly read `crackable_set=no`, while the bin with all three read `yes`. This proves the flag keys on the **SAM+SYSTEM pairing specifically** (the cryptographically meaningful one — SAM = hashes, SYSTEM = boot key), not on "≥2 hives" generically.
- **Time-window note.** The three `reg save` events (test 1) and the `esentutl` attempt fell into one 5-minute bin; the `reg export` runs into later bins. When validating, widen the time picker enough to span the whole session — "Last 15 minutes" rolled past the earliest `reg save` bin by the time the secondary was run, so its `crackable_set=yes` row came from the `reg export` trio instead. Both prove the same logic.

## False Positive Considerations

Genuinely near-zero, but the handful of real causes:

- **Backup / forensic / IR tooling.** Legitimate backup agents and DFIR collection scripts sometimes `reg save` or VSS-copy the hives as part of a full-system capture. Identifiable by the tool's signed parent process and a known collection window/account. Allowlist the specific agent + account, not the technique.
- **`esentutl` for its real job.** `esentutl.exe` is a legitimate ESE-database maintenance tool (Exchange, AD `ntds.dit`, Windows Search). Benign `esentutl` runs operate on `.edb`/`.jfm` files and **lack `/vss` against a `\config\` hive** — the classifier's `/vss` + hive-path conjunction keeps those out.
- **`reg save` of application keys.** Admins and installers back up `HKLM\SOFTWARE\…` subkeys routinely. The `HKLM\(sam|system|security)` anchor excludes these — only the credential hives alert.
- **Genuine admin doing a manual SAM backup.** Rare and attributable; a quick confirm-with-the-human, not a silent allowlist.

**Tuning recommendations:**

1. **Alert on the primary; escalate on the secondary.** Any single classified row is high-severity; a `crackable_set=yes` burst is critical — the adversary has the offline-crackable set in hand.
2. **Pivot to the dump-file artifact.** Once a `reg save` fires, pivot to Sysmon **EID 11** for a file *create* at the save destination (`%temp%\sam` and friends) — the artifact confirms the dump completed and gives the exact file to scope for cleanup. (Worth adding as a tertiary EID 11 search in the validated version.)
3. **Correlate backward to the impair step.** A SAM dump is almost always immediately preceded by a Defender disable ([T1562.001](T1562.001-impair-defenses.md)) in the same session — pivot back to confirm the full impair→dump chain and establish the attacker's session start.
4. **Watch for the hive-set, not just SAM.** A lone SAM grab is suspicious; SAM+SYSTEM together means they can actually crack — prioritise `crackable_set=yes`.

### Analyst notes on this real event

- **`CommandLine: reg save HKLM\sam C:\Users\analyst\AppData\Local\Temp\sam`** — the sharp signature. There is no benign reason to save the SAM hive; this single line *is* the alert. The destination (`…\Temp\sam`) is the artifact to scope for an EID 11 file-create pivot and for cleanup (it holds real local-account hashes).
- **`ParentCommandLine: "cmd.exe" /c reg save HKLM\sam … & reg save HKLM\system … & reg save HKLM\security …`** — the single most useful field in the event. Even though this child only saved SAM, its **parent line reveals the whole crackable trio** (SAM + SYSTEM + SECURITY) was grabbed in one chained command. An analyst triaging *any one* of the three child rows immediately sees the full intent. This is also why `ParentImage` is `cmd.exe`, not `powershell.exe` — these atomics are cmd-based, so the [§10 ART-runner caveat](../notes/splunk-spl-cheatsheet.md) doesn't apply.
- **`IntegrityLevel: High`** — the dump requires elevation (the hive is admin-only via the backup privilege `reg save` uses). A `reg save HKLM\sam` from a *medium*-integrity process would be an even louder anomaly.
- **`User: DESKTOP-0DU4BT6\analyst`** — clean process attribution, because `reg save` goes through a real `reg.exe` process. Contrast [T1562.001](T1562.001-impair-defenses.md)'s `Set-MpPreference`, where the change was brokered by `MsMpEng`/`SYSTEM` and the human actor was invisible to the registry event — here the actor is right in the EID 1.
- **`Hashes: …IMPHASH=…`** — Sysmon's hashes of the `reg.exe` binary. Native and unmodified here, but on a host where an attacker dropped a renamed/trojanised `reg.exe`, the hash mismatch against the known-good system binary would be an extra signal.
