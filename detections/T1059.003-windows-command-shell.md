# Detection: Windows Command Shell (cmd.exe) Abuse

> **Status: validated 2026-06-08.** The weighted-score SPL fired end-to-end against Atomic Red Team `T1059.003-2/3/5/6` on the soc-victim VM, producing exactly the designed score separation: the benign baseline (test 2) stayed **silent** while the three evasion atomics surfaced — `obfuscation` for test 3 (score 2), `stdin_redir` for test 5 (2), `script_drop`+`recon_chain` for test 6 (3). The pre-flight open question (see Tuning Notes) resolved in the detection's favor: the `%LOCALAPPDATA:~-3,1%` obfuscation **does** survive to the captured `CommandLine` (as `%%…%%`), so `obfuscation` matched on real argv — and the *expanded* child it spawns (`cmd /c echo Hello…`) scored a clean 0, confirming the detection fires on the obfuscated parent, not the benign child. The Sample Event below is a real captured EID 1. **Note `susp_parent` is structurally unexercised under ART** — every atomic is parented by the `powershell.exe` test runner — so its production value (Office/script-host-spawned shells) is reasoned, not lab-proven; see Tuning Notes.

## MITRE ATT&CK

- **Tactic:** Execution (TA0002)
- **Technique:** T1059.003 — Command and Scripting Interpreter: Windows Command Shell

## Severity

**Variable (Low baseline, High in context)** — This is the hardest-to-tune technique in the lab so far. `cmd.exe` is the single most-run binary on a normal Windows host: installers shell out to it, scheduled tasks wrap commands in it, login scripts use it, and admins live in it. A detection that simply alerts on `Image=*\cmd.exe` would bury the SOC in thousands of benign events a day and is worse than useless.

The detectable signal is never "cmd ran" — it's **how and from where** cmd ran:

- **Suspicious parent** — `cmd.exe` spawned by a Microsoft Office app (`winword.exe`, `excel.exe`), a script host (`wscript.exe`, `mshta.exe`), or a document-handler (`hh.exe`, `eqnedt32.exe`) is the textbook *execution-after-initial-access* signal. Word does not normally launch a command shell.
- **Download-and-execute payloads** — `/c` lines that invoke `certutil`, `bitsadmin`, `curl`, or `powershell -enc` to pull and run a second stage.
- **Obfuscation** — caret escaping (`c^m^d`), environment-variable substring tricks (`%COMSPEC%`, `%PATH:~...%`), and `set`-variable indirection used to evade naive string matching.

So this write-up deliberately does **not** use a single hard `| where`. It uses a **weighted-scoring** model (a new pattern for this lab) so the analyst gets a ranked queue instead of a binary alert — high-confidence combinations float to the top, weak single signals stay visible but quiet.

## Detection Logic

Both searches key off Sysmon **EID 1** (process creation), scoped to `Image=*\cmd.exe`.

### Primary — risk-flag classifier (hunting / pivot)

Decorates every `cmd.exe` execution with independent `yes/no` risk indicators. The analyst sorts on the indicator columns in the UI to triage — nothing is dropped, so a false negative just leaves a flag at `no` rather than hiding the event (the decorate-don't-drop pattern from the [SPL cheatsheet §8](../notes/splunk-spl-cheatsheet.md)).

```spl
index=endpoint sourcetype="WinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
Image="*\\cmd.exe"
| eval susp_parent=if(match(ParentImage, "(?i)\\\\(winword|excel|powerpnt|outlook|onenote|mshta|wscript|cscript|hh|eqnedt32|cmstp|wmiprvse)\.exe$"), "yes", "no")
| eval encoded_ps=if(match(CommandLine, "(?i)(powershell|pwsh)\b") AND match(CommandLine, "(?i)\s-(e|en|enc|enco|encod|encode|encoded|encodedc|encodedco|encodedcom|encodedcomm|encodedcomma|encodedcomman|encodedcommand)\s"), "yes", "no")
| eval download_exec=if(match(CommandLine, "(?i)\b(certutil|bitsadmin|curl|wget|regsvr32|rundll32|mshta)\b"), "yes", "no")
| eval obfuscation=if(match(CommandLine, "(?i)(\^|%comspec%|%[a-z0-9_]+:~)"), "yes", "no")
| eval stdin_redir=if(match(CommandLine, "(?i)\s/r\b") OR match(CommandLine, "(?i)\bcmd(\.exe)?\s*<"), "yes", "no")
| eval script_drop=if(match(CommandLine, "(?i)>\s*\S+\.(vbs|js|jse|wsf|hta|bat|cmd|ps1)\b"), "yes", "no")
| eval recon_chain=if(match(CommandLine, "(?i)\b(whoami|systeminfo|ipconfig|nltest|tasklist|netstat)\b") OR match(CommandLine, "(?i)\bnet1?\s+(user|group|localgroup)\b"), "yes", "no")
| eval acct=coalesce(mvindex(mvfilter(User!="NOT_TRANSLATED"),0), User)
| table _time host acct ParentImage Image susp_parent encoded_ps download_exec obfuscation stdin_redir script_drop recon_chain CommandLine ParentCommandLine
| sort - _time
```

### Secondary — weighted-score alert (the real alert)

Each indicator carries a weight reflecting how strongly it predicts malice on its own; the score is summed and thresholded. A suspicious parent or encoded PowerShell crosses the bar alone (weight 3); the weaker signals must combine.

```spl
index=endpoint sourcetype="WinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
Image="*\\cmd.exe"
| eval susp_parent=if(match(ParentImage, "(?i)\\\\(winword|excel|powerpnt|outlook|onenote|mshta|wscript|cscript|hh|eqnedt32|cmstp|wmiprvse)\.exe$"), 3, 0)
| eval encoded_ps=if(match(CommandLine, "(?i)(powershell|pwsh)\b") AND match(CommandLine, "(?i)\s-(e|en|enc|enco|encod|encode|encoded|encodedc|encodedco|encodedcom|encodedcomm|encodedcomma|encodedcomman|encodedcommand)\s"), 3, 0)
| eval download_exec=if(match(CommandLine, "(?i)\b(certutil|bitsadmin|curl|wget|regsvr32|rundll32|mshta)\b"), 2, 0)
| eval obfuscation=if(match(CommandLine, "(?i)(\^|%comspec%|%[a-z0-9_]+:~)"), 2, 0)
| eval stdin_redir=if(match(CommandLine, "(?i)\s/r\b") OR match(CommandLine, "(?i)\bcmd(\.exe)?\s*<"), 2, 0)
| eval script_drop=if(match(CommandLine, "(?i)>\s*\S+\.(vbs|js|jse|wsf|hta|bat|cmd|ps1)\b"), 2, 0)
| eval recon_chain=if(match(CommandLine, "(?i)\b(whoami|systeminfo|ipconfig|nltest|tasklist|netstat)\b") OR match(CommandLine, "(?i)\bnet1?\s+(user|group|localgroup)\b"), 1, 0)
| eval score=susp_parent + encoded_ps + download_exec + obfuscation + stdin_redir + script_drop + recon_chain
| where score >= 2
| eval acct=coalesce(mvindex(mvfilter(User!="NOT_TRANSLATED"),0), User)
| table _time host acct ParentImage Image score susp_parent encoded_ps download_exec obfuscation stdin_redir script_drop recon_chain CommandLine
| sort - score, - _time
```

### What each piece does

- **`susp_parent` (weight 3).** A command shell whose parent is an Office app or script host is the classic macro/phishing execution chain — Word doesn't spawn `cmd.exe` in normal use. `wmiprvse.exe` parent catches WMI-based remote execution (`win32_process create`). *Lab caveat: this flag does not fire under Atomic Red Team, which parents every atomic under `powershell.exe` (the test runner) — see Tuning Notes. It is the highest-priority signal in production but unexercised by our test harness.*
- **`encoded_ps` (weight 3).** A `cmd /c powershell -enc ...` hand-off — `cmd` shelling out to an encoded PowerShell payload. The flag enumerates every valid prefix of `-EncodedCommand` whitespace-anchored, reusing the exact pattern hardened in [T1059.001](T1059.001-powershell-encoded.md) and [cheatsheet §3](../notes/splunk-spl-cheatsheet.md) — substring-matching `-enc` would both over-match parameter names and miss the `-e` short form.
- **`download_exec` (weight 2).** LOLBin downloaders (`certutil -urlcache`, `bitsadmin /transfer`, `curl`) inside a `/c` line.
- **`obfuscation` (weight 2).** Caret escaping (`^`), `%COMSPEC%` indirection, and `%VAR:~start,len%` substring extraction — all evasion tricks with essentially no benign use in an interactive command line. **This is the flag ART `T1059.003-3` exercises** (`%LOCALAPPDATA:~-3,1%md` assembles the string `cmd` one character at a time to dodge naive `cmd` string-matching).
- **`stdin_redir` (weight 2).** The `cmd /r cmd<"file"` stdin-redirection pattern — feeding a script into `cmd` via standard-in rather than as an argument, so the actual commands never appear on any command line. Named in the Raspberry Robin reporting; **exercised by ART `T1059.003-5`**. `/r` is an undocumented alias of `/c` that legitimate software essentially never uses.
- **`script_drop` (weight 2).** `cmd` redirecting (`>`) into a script file (`.vbs`/`.js`/`.hta`/`.bat`/`.ps1`/…) — the echo-a-script-to-disk-then-run-it staging pattern. **Exercised by ART `T1059.003-6`** (DarkGate second-stage simulation: `echo Set objShell... > AtomicTest.vbs & AtomicTest.vbs`).
- **`recon_chain` (weight 1).** Discovery commands (`whoami`, `ipconfig`, `net user`, …) embedded in the `/c`. Lowest weight because these are individually common, but they corroborate. Overlaps intentionally with [T1087](T1087-account-discovery.md)/[T1082](T1082-system-info-discovery.md) — here a corroborating weight, there the primary signal.
- **Binary classified off `Image`, arguments off `CommandLine`** — the recurring lab lesson (cheatsheet, T1087 fix #1). The shell binary is matched on `Image=*\cmd.exe`; everything else inspects `CommandLine`/`ParentImage`.
- **`acct` dedup** — the multivalued-`User` coalesce ([T1087 fix #2](T1087-account-discovery.md)), so each row reports one account.

**The threshold (`score >= 2`) is the primary tuning knob.** It was lowered from an initial 3 to 2 during pre-flight analysis (see Tuning Notes): because each T1059.003 sub-technique trips exactly *one* flag, a single-technique event scores the weight of that one flag. At threshold 2, any single weighted indicator fires (suspicious parent, encoded PS, download, obfuscation, stdin-redirection, or script-drop), while a lone `recon_chain` (weight 1) stays quiet — exactly the desired line. The 3-vs-2 weights still matter: they rank the queue (`sort - score`), floating an Office-macro-plus-encoded-PS event (6) above a lone obfuscation (2). Raise toward 4–5 only if the lab baseline proves noisy.

## Why This Works

`cmd.exe` is an *interpreter*, so adversaries reach for it constantly — but they reach for it in shapes that legitimate software does not. A human admin running `ipconfig` types it at an already-open prompt; malware spawns a fresh `cmd /c` from whatever foothold it has (a macro, a script host, a service) and chains its whole next step into one line. That **parentage + payload shape** is the discriminator, not the mere presence of the shell.

The weighted score encodes the analyst's mental triage model directly: *where did this shell come from, and what is it about to do?* An Office-parented shell running an encoded PowerShell downloader scores 8 and sits at the top of the queue; a login script running `ipconfig` scores 1 and never alerts. No single rule could separate those — but the sum does.

## Tuning Notes

**Pre-flight calibration (2026-06-08) — the draft was retuned *before* the first execution.** Reviewing the actual ART atomic command blocks (`-ShowDetails`) revealed the first-draft model was tuned for the wrong archetype and would have "validated" by detecting nothing. The findings, and the changes they forced:

- **The ART runner parents every atomic under `powershell.exe`.** The `command_prompt` executor is launched by the `Invoke-AtomicTest` PowerShell session, so the spawned `cmd.exe` has `ParentImage=...\powershell.exe` — which is deliberately *not* in `susp_parent` (adding it would flood the flag). **Consequence:** `susp_parent` (the strongest production signal) is structurally unexercisable in this lab. Every atomic must therefore score on *payload* signals alone. This is a property of the test harness, not the detection — documented rather than "fixed."
- **Each sub-technique trips exactly one flag**, so a single-technique atomic scores that one flag's weight. The first-draft threshold of 3 meant the canonical "Suspicious Execution" atomic (`T1059.003-3`, obfuscation, weight 2) would have **missed**. **Fix:** lowered threshold to `>= 2` and confirmed a lone `recon_chain` (weight 1) still stays under it.
- **`T1059.003-3` drove the `obfuscation` flag design.** Its command is `%LOCALAPPDATA:~-3,1%md /c echo ...` — the `%VAR:~offset,len%` substring trick extracts the character `c` from `...Local` to assemble `cmd` and dodge literal `cmd` matching. The `%[a-z0-9_]+:~` branch of the obfuscation regex is aimed squarely at this. **Open question for validation:** whether the literal `%LOCALAPPDATA:~-3,1%` survives to the captured `CommandLine`, or whether ART's executor writes the command to a temp `.bat` first (in which case the obfuscation lives *inside* the script file and the `cmd.exe` argv is just `cmd /c "...temp.bat"` — and `obfuscation` would not match). **This is the single most important thing to confirm from the real event.**
- **`T1059.003-5` (Raspberry Robin) added `stdin_redir`.** `cmd /r cmd<"file.cmd"` feeds commands via stdin; nothing meaningful appears on the command line. Without a dedicated flag this atomic scored 0. The `stdin_redir` flag matches the `/r` alias and the `cmd<` redirection — but note it is *inherently* a partial detection: the payload itself is invisible to command-line logging, which is the whole point of the technique.
- **`T1059.003-6` (DarkGate) added `script_drop`.** `echo Set objShell...whoami... > AtomicTest.vbs & AtomicTest.vbs` writes a VBScript then runs it. Scores `script_drop` (2) + `recon_chain` (1, the embedded `whoami`) = 3. Note this atomic *also* spawns `wscript.exe`→`whoami.exe`, a chain a `cmd`-scoped detection can't see — a cross-process correlation opportunity for later.

**Predicted scores going into validation** (threshold `>= 2`): `T1059.003-2` → **0** (benign baseline, must not fire), `-3` → **2** (obfuscation, *if* argv-visible), `-5` → **2** (stdin_redir), `-6` → **3** (script_drop + recon).

**Validation result (2026-06-08) — all four predictions confirmed.** The classifier table over the 9 captured `cmd.exe` events showed exactly the expected separation:

| Atomic | Captured `CommandLine` (abridged) | Flag fired | Score |
|---|---|---|---|
| `-2` | `"cmd.exe" /c echo "Hello…" > "%%TEMP%%\test.bin" & type …` | — | **0** (silent ✓) |
| `-3` | `"cmd.exe" /c %%LOCALAPPDATA:~-3,1%%md /c echo … > hello.txt …` | `obfuscation` | **2** ✓ |
| `-5` | `"cmd.exe" /c cmd /r cmd<"…\t1059.003_cmd.cmd"` | `stdin_redir` | **2** ✓ |
| `-6` | `"cmd.exe" /c … echo Set objShell…Exec("whoami")… > AtomicTest.vbs & AtomicTest.vbs` | `script_drop` + `recon_chain` | **3** ✓ |

**The pre-flight open question is resolved: ART passes the command inline, not via a temp `.bat`.** The captured argv contained the literal obfuscation token `%%LOCALAPPDATA:~-3,1%%` (percents doubled by ART's executor, but the `%[a-z0-9_]+:~` regex matches the inner `%LOCALAPPDATA:~` regardless), so `obfuscation` fired on real command-line data. Corroborating evidence the model is precise rather than lucky: the env-var *expansion* produced a separate child event `cmd /c echo Hello, from CMD!` (no obfuscation token, score **0**) — the detection flags the obfuscated parent and correctly ignores the clean child. The `stdin_redir` flag likewise fired on both the test-5 wrapper and its `cmd /r cmd` child; the benign expanded children of test 5 (`cmd /c calc.exe`) and the test-6 `cd /d` sub-shell scored 0 as intended.

**Known false-negative class — renamed/relocated shells.** A payload that runs a renamed `cmd.exe`, or points `%ComSpec%` elsewhere, won't match `Image=*\cmd.exe`. Pivoting on `OriginalFileName=Cmd.Exe` (Sysmon EID 1 field) catches simple renames — complementary hardening to add once the core model is validated.

## False Positive Considerations

This is the noisiest technique in the lab; the FP discipline matters more here than anywhere prior.

- **Software installers and updaters** shelling out to `cmd /c` for file ops — dominant benign volume, but they rarely trip the *weighted* signals (no Office parent, no encoded PS).
- **Login / GPO startup scripts** running `ipconfig`, `net use`, `whoami` — will trip `recon_chain` (weight 1) but shouldn't cross 3 alone. If they do, allowlist by their parent (`userinit.exe`/`gpscript.exe`).
- **Legitimate admin automation** that genuinely uses `certutil`/`bitsadmin` for file transfer — the one place `download_exec` produces real FPs. Baseline and allowlist the specific admin host/account.
- **RMM and monitoring agents** that wrap commands in `cmd /c` — identify by parent (the agent's service binary) and exclude that parent.

**Tuning recommendations:**

1. **Alert on the weighted SPL, hunt on the classifier** — same split as T1087/T1082.
2. **Allowlist by `ParentImage`, not by lowering the threshold.** Installer/agent parents are stable; suppress the parent rather than blunting the score for everyone.
3. **Treat `susp_parent=3` as near-certain.** An Office or script-host-parented shell deserves its own higher-priority sub-alert regardless of payload.
4. **Cross-tactic correlation.** A scoring `cmd.exe` event that immediately precedes a T1087/T1082 discovery burst or a T1547.001 Run-key write is the recon-after-execution sequence — chain them later.

### Analyst notes on this real captured event

- **`CommandLine: "cmd.exe" /c %%LOCALAPPDATA:~-3,1%%md /c echo Hello, from CMD! > hello.txt & type hello.txt`** — the whole reason this event scores. `%LOCALAPPDATA%` resolves to `C:\Users\analyst\AppData\Local`; the `:~-3,1` slice takes one character starting three from the end → `c`, so `%LOCALAPPDATA:~-3,1%md` assembles the string `cmd`. The point is purely evasive: spell `cmd` out of an environment-variable substring so a literal `cmd` string-match never sees it. The `obfuscation` flag's `%[a-z0-9_]+:~` branch matches `%LOCALAPPDATA:~` regardless of the doubled `%%` ART's executor introduced. This is Red Canary's canonical 2021 example of the technique.
- **`ParentImage: ...\powershell.exe`, `ParentCommandLine: "...powershell.exe"`** — the bare-PowerShell parent is the **ART test runner**, not an adversary artifact. In a real intrusion the parent of an obfuscated `cmd` is the most interesting field (an Office app, `mshta`, a service); here it is a lab fixture, which is precisely why `susp_parent` did not fire and the detection had to carry this event on the payload signal alone. The lab structurally cannot exercise `susp_parent` — see Tuning Notes.
- **`OriginalFileName: Cmd.Exe`** — the binary's internal name. Pivoting on `OriginalFileName="Cmd.Exe"` catches a renamed `cmd.exe` that an `Image=*\cmd.exe` glob would miss (the complementary hardening noted in Tuning Notes).
- **`CurrentDirectory: C:\Users\analyst\AppData\Local\Temp\`** — ART staging. An obfuscated shell whose working directory is `\Temp\`/`\AppData\` is itself a triage signal in production.
- **`IntegrityLevel: High`** — the ART session was elevated, so this child `cmd` runs High. Integrity level is a useful secondary weight: a High-integrity obfuscated shell is worse than a Medium-integrity one.
- **The expanded child is a separate event.** `%LOCALAPPDATA:~-3,1%md` expands and spawns `cmd /c echo Hello, from CMD!` as its own EID 1 (different `ProcessId`) carrying **no** obfuscation token — scoring 0. The detection fires on *this* parent event, not the clean child, which is the precision check that the flag keys on the obfuscation itself rather than the mere presence of a second `cmd`.
- **`Hashes: ...SHA256=BADF4752…`** — the legitimate Microsoft-signed `cmd.exe`. The malice is entirely in the *arguments and parentage*, not the binary — the defining trait of a LOLBin technique, and why hash/signature controls are blind to it.
