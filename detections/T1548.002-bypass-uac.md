# Detection: Abuse Elevation Control Mechanism — Bypass User Account Control

> **Status: validated 2026-06-10/11.** Both searches ran end-to-end on soc-victim against five real Atomic Red Team tests (the ART catalog still ships T1548.002 — 27 tests in the install). The result was a textbook two-stage capture and three findings worth the write-up: (1) **3 bypasses/disables worked and lit both layers** — fodhelper, ComputerDefaults, and the `EnableLUA→0` disable; (2) **the Event Viewer (mscfile) bypass is broken on this Win10 build (19045)** — it planted the hijack (corroborator caught it) but ran at **Medium** integrity with no elevation, so the primary correctly stayed silent, a live proof of the two-stage *coverage* bonus (the corroborator catches the attempt even when the bypass fails); (3) **the sdclt Folder hijack fires one level deeper than the literature implies** — `sdclt.exe → control.exe → payload`, so the elevated child's parent is **`control.exe`, not `sdclt.exe`**; the draft's `ParentImage=sdclt.exe` rule missed it and was fixed live by adding a `control.exe`-parent vector (gated on High integrity). Defender real-time protection had to be **off** for the bypasses to spawn their payload (the launch is blocked as a known UAC-bypass behavior with RTP on) — an honest prerequisite, the same Defender-off window discipline as [T1003.002](T1003.002-sam-credential-access.md)/[T1562.001](T1562.001-impair-defenses.md). The Sample Events below are real captures from the run. See Tuning Notes for the full findings.

## MITRE ATT&CK

- **Tactic:** Privilege Escalation (TA0004) and Defense Evasion (TA0005)
- **Technique:** T1548 — Abuse Elevation Control Mechanism
- **Sub-technique:** T1548.002 — Bypass User Account Control

This write-up covers the two facets of the sub-technique that the current ART tests exercise on a single Win10 endpoint:

1. **UAC *bypass*** — the fileless, registry-hijack family (fodhelper, ComputerDefaults, Event Viewer, sdclt). The adversary plants a per-user shell-open-command hijack, then launches a Windows binary that **auto-elevates without a consent prompt** (`autoElevate=true` in its manifest); that binary reads the hijacked key and runs the attacker's payload at **High integrity**.
2. **UAC *disable*** — turning UAC off wholesale by writing `EnableLUA=0` (or weakening remote-UAC token filtering via `LocalAccountTokenFilterPolicy=1`) to the policy registry.

Both end at the same place — code running elevated that the user never consented to — so they belong in one detection.

## Severity

**High.** A UAC bypass is a privilege-escalation primitive: it takes a local-admin user's *medium*-integrity token to *high* with no consent prompt, which is the gate between "ran as the user" and "ran as the machine." It is almost never benign — legitimate elevation goes through the consent prompt (or an installer's elevated manifest), not through a fodhelper registry hijack. Like [T1562.001](T1562.001-impair-defenses.md) (disable Defender), this sits *immediately before* the payload in the kill chain: the adversary bypasses UAC to do the thing UAC would have prompted on — install a service, dump credentials ([T1003.002](T1003.002-sam-credential-access.md)), write to a protected path, disable Defender. A successful bypass is a high-confidence "the next action will be privileged" signal.

## Detection Logic

A UAC bypass is a **two-stage** action, and each stage leaves its own artifact:

| Stage | Signal | Channel / EID | Fires when | Catches |
|---|---|---|---|---|
| **Plant** | hijack-key write | Sysmon **EID 13** | A per-user `…\shell\open\command` value is set (`ms-settings`, `mscfile`, `Folder`, `exefile`), **or** a UAC policy value (`EnableLUA`, `LocalAccountTokenFilterPolicy`) | The **setup** — fires on the *attempt*, even if the bypass is later blocked/patched |
| **Trigger → payoff** | elevated child | Sysmon **EID 1** | An auto-elevating binary (`fodhelper`, `ComputerDefaults`, `eventvwr`, `sdclt`, `slui`, `wsreset`) spawns an unexpected child — a shell/LOLBin — at **High** integrity | The **success** — proof the bypass actually escalated, with full process attribution |

This is a relative of the [§11 effect-tripwire-vs-attribution](../notes/splunk-spl-cheatsheet.md) idiom, but with a meaningful difference worth calling out: in [T1070.001](T1070.001-clear-event-logs.md) and [T1547.001](T1547.001-registry-run-keys.md) the two events were *the same fact* seen by a universal service-written event and a partial process event. Here the two events are **two different moments of one technique** — the bait being planted (EID 13) and the trap springing (EID 1) — separated by however long the auto-elevate binary takes to fire. That changes the operational meaning:

- **EID 1 (elevated child) is the primary alert** — it is the sharpest, lowest-FP signal (`fodhelper.exe` spawning `cmd.exe` at High integrity is essentially never benign) and it confirms the escalation *succeeded*.
- **EID 13 (hijack-key write) is the corroborator with a coverage bonus**: because the registry write happens *before* the auto-elevate binary runs, it fires **even when the bypass itself is patched or fails** — so on a fully-patched host where the elevated child never spawns, the corroborator still catches the attempt. The two are complementary in *coverage*, not merely in *confidence*.

### Primary — elevated child of an auto-elevating binary / UAC policy disable (Sysmon EID 1)

```spl
index=endpoint sourcetype="WinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
(ParentImage="*\\fodhelper.exe" OR ParentImage="*\\ComputerDefaults.exe"
 OR ParentImage="*\\eventvwr.exe" OR ParentImage="*\\sdclt.exe" OR ParentImage="*\\control.exe"
 OR ParentImage="*\\slui.exe" OR ParentImage="*\\wsreset.exe"
 OR (Image="*\\reg.exe" AND (CommandLine="*EnableLUA*" OR CommandLine="*LocalAccountTokenFilterPolicy*")))
| eval method=case(
    match(ParentImage,"(?i)\\\\(fodhelper|computerdefaults)\.exe$") AND match(Image,"(?i)\\\\(cmd|powershell|pwsh|wscript|cscript|mshta|rundll32|regsvr32|wmic|notepad|conhost)\.exe$"), "UAC bypass — fodhelper/ComputerDefaults elevated child (ms-settings hijack)",
    match(ParentImage,"(?i)\\\\eventvwr\.exe$") AND NOT match(Image,"(?i)\\\\mmc\.exe$"), "UAC bypass — Event Viewer elevated child (mscfile hijack)",
    match(ParentImage,"(?i)\\\\sdclt\.exe$") AND NOT match(Image,"(?i)\\\\(control|sdclt)\.exe$"), "UAC bypass — sdclt elevated child (Folder hijack)",
    match(ParentImage,"(?i)\\\\control\.exe$") AND match(Image,"(?i)\\\\(cmd|powershell|pwsh|mshta|rundll32|regsvr32|wscript|cscript)\.exe$") AND match(IntegrityLevel,"(?i)^(High|System)$"), "UAC bypass — sdclt Folder hijack via control.exe (elevated child)",
    match(ParentImage,"(?i)\\\\(slui|wsreset)\.exe$") AND match(Image,"(?i)\\\\(cmd|powershell|pwsh|mshta|rundll32|regsvr32|wscript|cscript)\.exe$"), "UAC bypass — slui/WSReset elevated child",
    match(Image,"(?i)\\\\reg\.exe$") AND match(CommandLine,"(?i)\bEnableLUA\b") AND match(CommandLine,"(?i)/d\s+0\b"), "UAC disabled via registry (EnableLUA -> 0)",
    match(Image,"(?i)\\\\reg\.exe$") AND match(CommandLine,"(?i)\bLocalAccountTokenFilterPolicy\b") AND match(CommandLine,"(?i)/d\s+1\b"), "Remote-UAC token filtering disabled (LocalAccountTokenFilterPolicy -> 1)"
  )
| where isnotnull(method)
| eval acct=coalesce(mvindex(mvfilter(User!="NOT_TRANSLATED"),0), User)
| table _time host acct method IntegrityLevel Image ParentImage CommandLine ParentCommandLine
| sort - _time
```

### Corroborator — hijack-key / UAC-policy registry write (Sysmon EID 13)

```spl
index=endpoint sourcetype="WinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=13
(TargetObject="*\\ms-settings\\shell\\open\\command\\*"
 OR TargetObject="*\\mscfile\\shell\\open\\command\\*"
 OR TargetObject="*\\Folder\\shell\\open\\command\\*"
 OR TargetObject="*\\exefile\\shell\\open\\command\\*"
 OR TargetObject="*\\Policies\\System\\EnableLUA"
 OR TargetObject="*\\Policies\\System\\LocalAccountTokenFilterPolicy")
| eval setting=case(
    match(TargetObject,"(?i)\\\\ms-settings\\\\shell\\\\open\\\\command\\\\"), "Hijack: ms-settings\\shell\\open\\command (fodhelper / ComputerDefaults)",
    match(TargetObject,"(?i)\\\\mscfile\\\\shell\\\\open\\\\command\\\\"), "Hijack: mscfile\\shell\\open\\command (Event Viewer)",
    match(TargetObject,"(?i)\\\\Folder\\\\shell\\\\open\\\\command\\\\"), "Hijack: Folder\\shell\\open\\command (sdclt)",
    match(TargetObject,"(?i)\\\\exefile\\\\shell\\\\open\\\\command\\\\"), "Hijack: exefile\\shell\\open\\command",
    match(TargetObject,"(?i)\\\\EnableLUA$"), "UAC disabled (EnableLUA)",
    match(TargetObject,"(?i)\\\\LocalAccountTokenFilterPolicy$"), "Remote-UAC token filtering disabled (LocalAccountTokenFilterPolicy)",
    1=1, "UAC-related registry change"
  )
| eval is_delegate=if(match(TargetObject,"(?i)\\\\DelegateExecute$"),"yes","no")
| eval acct=coalesce(mvindex(mvfilter(User!="NOT_TRANSLATED"),0), User)
| table _time host acct setting is_delegate Details Image TargetObject RuleName
| sort - _time
```

### What each piece does

**Primary (EID 1):**

- **Binary off `Image`, parent off `ParentImage`, arguments off `CommandLine`** — the recurring lab discipline ([§3](../notes/splunk-spl-cheatsheet.md), T1087 fix #1). The auto-elevate binaries are matched on `ParentImage` (they are the *parent* of the payload); `reg.exe` on `Image`; the `EnableLUA`/`/d 0` arguments on `CommandLine`.
- **The parent/child anomaly is the signature.** Each auto-elevating binary has a known-legitimate behaviour, and the bypass violates it:
  - `fodhelper.exe` (the "Optional features" settings helper) and `ComputerDefaults.exe` ("Default apps") legitimately spawn essentially nothing — they hand off to the immersive Settings UI. **Any** shell/LOLBin child is anomalous.
  - `eventvwr.exe` legitimately spawns `mmc.exe` (it hosts the Event Viewer snap-in). A **non-`mmc`** child is the tell — hence `NOT match(Image, "…\\mmc\.exe$")`.
  - `sdclt.exe` (Backup and Restore) legitimately spawns `control.exe` / re-launches itself. A `cmd`/`powershell` child *of `sdclt.exe`* is the tell — **but in the lab the real elevated payload appeared one hop deeper** (see next bullet).
- **The `control.exe` vector — a live calibration fix.** The sdclt Folder-hijack does **not** spawn its payload as a direct child of `sdclt.exe`. The observed chain was `sdclt.exe (High) → control.exe /name Microsoft.BackupAndRestoreCenter (High) → cmd.exe /c notepad.exe (High)` — i.e. it is **`control.exe`** that touches the hijacked `Folder` object and launches the payload, so the elevated child's `ParentImage` is `control.exe`, not `sdclt.exe`. The draft's `ParentImage=sdclt.exe` rule missed it entirely. The fix adds a dedicated case — `ParentImage=control.exe` AND a shell/LOLBin child AND `IntegrityLevel∈{High,System}` — *gated on High integrity* because `control.exe` is more general than the auto-elevate binaries (a Medium `control→cmd` is a likelier benign edge case, so the High gate keeps this vector tight). This is the lab's recurring "field/relationship *shape* assumptions are where detections quietly break" lesson, applied to a parent/child chain ([§3](../notes/splunk-spl-cheatsheet.md), and the same family as the T1547 RunOnceEx and T1053 `schtasks→svchost` surprises).
- **`IntegrityLevel` is tabled (and gated only on the `control.exe` vector).** A successful bypass produces a `High` (or `System`) child — that is the whole point, the medium→high jump. For the auto-elevate-binary cases it is tabled as confirmation rather than required (the parent/child relationship is already sharp enough to carry the alert); for the broader `control.exe` vector it *is* required in the `where` via the case condition, as just described. Live, every successful bypass child came back `High` and every planted-but-failed one (Event Viewer) was `Medium` — so the integrity level cleanly separated the bypasses that elevated from the one that did not.
- **The `EnableLUA -> 0` value-direction anchor.** As with the [T1562.001](T1562.001-impair-defenses.md) `-DisableRealtimeMonitoring $true` test, the *direction* matters: `EnableLUA /d 0` **disables** UAC (malicious); the ART cleanup writes `/d 1` to **re-enable** it. Matching `/d 0` flags only the disable, not the restore. `LocalAccountTokenFilterPolicy` is the inverse — `/d 1` is the weakening direction.
- **`| where isnotnull(method)`** — the positive-classifier discipline ([§11 rule 1](../notes/splunk-spl-cheatsheet.md), the T1070.001 `wevtutil` lesson). We classify only the known-bad parent/child and value shapes and drop everything else, rather than ending on a `1=1` catch-all that would surface every benign `mmc` launch from `eventvwr`.
- **`acct` dedup** — the multivalued-`User` coalesce ([T1087 fix #2](T1087-account-discovery.md)).

**Corroborator (EID 13):**

- **Anchors on the four abused shell-open-command classes plus the two UAC policy values.** `ms-settings`, `mscfile`, `Folder`, and `exefile` are the registry classes the documented bypasses hijack; a per-user (`HKU\<SID>\…`) write to any of their `\shell\open\command` subkeys is the bait being planted. `EnableLUA` / `LocalAccountTokenFilterPolicy` are the wholesale-disable values.
- **`is_delegate` flag.** The fodhelper/ComputerDefaults technique sets *two* values: the `(Default)` (the payload command) and an empty `DelegateExecute`. The empty `DelegateExecute` is what forces the shell to honour the `(Default)` command instead of the protocol handler — it is a near-pathognomonic marker of this specific bypass. Flagging it separates the "smoking-gun" write from the payload write.
- **`Details` is tabled** to show the planted payload — for the fodhelper test the `(Default)` write carries `C:\Windows\System32\cmd.exe`, i.e. exactly what is about to run elevated.
- **`RuleName` is tabled** because it carries the SwiftOnSecurity config's own ATT&CK tag — and this is the [pre-flight teaching point](#tuning-notes): the hijack-key writes are caught by the config's **generic** `\command\` rule (`setup/sysmon-config.xml:652`, tagged **`T1042`** — "Default File Association changes"), *not* a UAC-specific rule, while the `EnableLUA`/`LocalAccountTokenFilterPolicy` writes are caught by the explicit **`T1088`** rules (`sysmon-config.xml:730-731` — T1088 is the pre-rename ATT&CK ID for "Bypass UAC", the same generation gap as `T1060,RunKey` in [T1547.001](T1547.001-registry-run-keys.md) and `T1089,Tamper-Defender` in [T1562.001](T1562.001-impair-defenses.md)).

## Why This Works

The structural point is the same family as the Run-key, log-clear, and Defender detections: **the technique cannot reach its goal without writing the exact artifacts we watch.** A fileless UAC bypass is *defined by* the registry hijack — there is no way to make `fodhelper.exe` run your payload without first writing the `ms-settings\shell\open\command` value (EID 13), and there is no way to collect the elevated token without `fodhelper.exe` actually spawning your payload (EID 1). The two artifacts are not incidental side effects; they are the mechanism.

And because the Universal Forwarder ships each event off-host the instant it is written, both the plant and the payoff are recorded on the Splunk indexer in real time — so even a bypass that immediately deletes its own hijack key in cleanup (every ART test does) has already been recorded off-box. The cleanup `reg delete` removes the *evidence on disk*; it does nothing about the EID 13 already sitting in `index=endpoint`. Same "the act is already off-box before you can erase it" inversion as [T1070.001](T1070.001-clear-event-logs.md).

The one honest limit: a bypass that abuses a binary or class **not** in our parent list / hijack-class list would evade the primary, and one whose registry key the Sysmon config does not monitor would evade the corroborator. This detection covers the documented, ART-exercised families; UACME ships 70-plus methods, and a complete program treats this as a *coverage* list to extend, not a solved problem. See False Positives and Tuning for the specific gaps.

## Tuning Notes

**Validation findings (2026-06-10/11) — what the live run taught us:**

- **The corroborator works, and it rides on a *generic* rule — confirmed.** The make-or-break pre-flight question was whether the SwiftOnSecurity config catches the hijack keys at all, since it has no rule named for `ms-settings`/`mscfile`. It does, via the **generic** line 652 — `<TargetObject name="T1042" condition="contains">\command\</TargetObject>`. The captured EID 13s confirm the rendering the rule depends on: `…\ms-settings\shell\open\command\(Default)` and `…\command\DelegateExecute`, both carrying the `\command\` substring, both tagged `RuleName: T1042`. So this technique is visible only because a broad shell-hijack rule happens to cover it — a useful reminder that coverage can come from a rule that wasn't written with your technique in mind.
- **Registry rendering quirk — `HKU\<SID>_Classes\…`.** The per-user class hive renders as `HKU\S-1-5-21-…-1001_Classes\ms-settings\shell\open\command\(Default)` — note the **`_Classes` suffix appended to the SID with *no* backslash separator** (it is *not* `HKU\<SID>\Software\Classes\…`). The SPL anchors from `\ms-settings\…` onward so it matches regardless, but this is a specific rendering to remember, alongside the [T1547.001 `HKU\<SID>` note](T1547.001-registry-run-keys.md): the HKCU classes redirection collapses to a `<SID>_Classes` key, not a nested `Software\Classes` path.
- **Writer-attribution split, confirmed live.** The **cmd-based** tests (fodhelper-cmd, eventvwr-cmd, disable-UAC) wrote the registry via `Image=…\reg.exe`; the **PowerShell-based** tests (ComputerDefaults, sdclt) wrote via `Image=…\powershell.exe`. Both name `User=DESKTOP-0DU4BT6\analyst` directly — because these are the user writing their *own* `HKU\…_Classes` hive, performed by the calling process itself with no broker. This is the clean contrast that makes the [T1562.001 `MsMpEng`/`SYSTEM` broker finding](T1562.001-impair-defenses.md) meaningful: there a *service* brokered an `HKLM` Defender write and the EID 13 named the broker, not the actor; here the user writes their own hive and the EID 13 *does* name the actor.
- **The ART-parent caveat does *not* apply here — confirmed, a notable exception ([§10](../notes/splunk-spl-cheatsheet.md)).** ART parents every atomic under its `powershell.exe` runner, which normally makes any parent-anchored flag unexercisable (the T1059.003 `susp_parent` lesson). Not here: the captured payoff has `ParentImage=C:\Windows\System32\fodhelper.exe`, because the **OS auto-elevate binary** read the registry and called `CreateProcess` on the payload — the parent is genuine, OS-set, and the parent-anchored primary is fully lab-provable. First lab detection whose core signal is a parent/child relationship ART can actually exercise.
- **The two-stage coverage bonus, proven live (the headline).** Five tests planted a hijack/policy write (all five caught by the corroborator); only **three actually elevated** and showed in the success-only primary. The **Event Viewer (mscfile) bypass is broken on Win10 19045**: `cmd /c eventvwr.msc` invoked the hijacked `mscfile` handler and spawned `cmd.exe` — but at **Medium** integrity, parented by the executor `cmd.exe`, *not* via `eventvwr.exe`'s auto-elevation, so no privilege jump occurred. The primary correctly stayed silent (no `eventvwr.exe` parent, and the child was Medium); the corroborator still caught the mscfile plant. That asymmetry — **EID 1 goes silent on a failed bypass while EID 13 still fires on the attempt** — is exactly why the corroborator is not optional: it is the only signal that survives a patched/failed bypass. Intent-not-outcome ([§ quirks](../notes/splunk-spl-cheatsheet.md)), at the technique-coverage level.
- **The `control.exe` calibration fix (the one real detection bug found).** The sdclt Folder hijack *did* elevate — `sdclt.exe (High) → control.exe /name Microsoft.BackupAndRestoreCenter (High) → cmd.exe /c notepad.exe (High)` — but the elevated payload's parent is **`control.exe`**, a hop below `sdclt.exe`. The draft's `ParentImage=sdclt.exe` rule missed it; meanwhile the *benign* part of that same chain (`sdclt → control.exe` itself) was correctly **not** flagged thanks to the `NOT (control|sdclt)` exclusion. Fixed live by adding a `ParentImage=control.exe` + shell-child + High-integrity case, which then classified the payload as `UAC bypass — sdclt Folder hijack via control.exe`. Same "the real parent isn't what the writeup says" family as the [T1053.005 `schtasks→svchost`](T1053.005-scheduled-task.md) and [T1547.001 RunOnceEx](T1547.001-registry-run-keys.md) surprises.
- **Defender is a hard prerequisite for the bypass *payload*.** With real-time protection **on**, the first fodhelper run failed with `Exception calling "Start" … "Access is denied"` and **nothing** landed in the index — Defender blocked the launch as a known UAC-bypass behavior before the `reg.exe` plant even ran. With RTP off (Tamper Protection off in GUI first, then `Set-MpPreference -DisableRealtimeMonitoring $true`), the full chain fired. Honest tooling caveat, the same Defender-off discipline as [T1003.002](T1003.002-sam-credential-access.md)/[T1562.001](T1562.001-impair-defenses.md) — and itself a detection data point: a real fodhelper bypass attempt on a Defender-protected host may surface first as a Defender block event rather than as the elevated child.

**For future runs — the cheap pre-flight that still applies:** confirm EID 13 is flowing generally (`index=endpoint EventCode=13 | stats count`) and run one fodhelper test first to re-confirm the `\command\` rule still catches the hijack before trusting the corroborator on a new image or a re-tuned Sysmon config.

## False Positive Considerations

The benign rate is low but not zero:

- **`eventvwr.exe → mmc.exe` is normal** and is the reason for the `NOT mmc` clause. An admin opening Event Viewer produces exactly this parent/child pair at High integrity; without the exclusion it would be a constant FP. (The bypass is betrayed by a *non-mmc* child.)
- **The `control.exe` vector is the FP-prone one** — `control.exe` is the general Control Panel host, far more common than the auto-elevate binaries, so a `control.exe → cmd/powershell` match is the most likely benign hit (an admin launching a Control Panel applet that legitimately shells out). Two things keep it tight: it is **gated on High integrity** (a benign `control→cmd` is usually Medium), and the shell child of an *elevated* Control Panel is genuinely unusual. If it proves noisy in a given environment, tighten further by requiring the grandparent `sdclt.exe` (via a `transaction`/`stats` over `ProcessGuid`→`ParentProcessGuid`) or anchor on `ParentCommandLine="*Microsoft.BackupAndRestoreCenter*"`. In the lab the only hit was the real bypass.
- **Legitimate file-association changes** can write `…\shell\open\command` values — an installer registering a new file type, a "set as default app" action. These differ from the bypass in three ways the corroborator surfaces: they target an application's own ProgID (not `ms-settings`/`mscfile`/`Folder`), they rarely write an empty `DelegateExecute` (`is_delegate=no`), and the `Details` payload points at the application, not `cmd.exe`/`powershell.exe`. The leading filter is already restricted to the four abused classes, which keeps most of this out.
- **Software that legitimately elevates** does so through the consent prompt or an elevated manifest, producing a `consent.exe` / UAC dialog — not a `fodhelper`-parented shell. The bypass's defining trait is elevation *without* `consent.exe` in the chain; that is a useful corroborating pivot.
- **Admin disabling UAC deliberately** (a lab build step, a kiosk image) writes `EnableLUA=0`. Identifiable: interactive admin session, a known build/maintenance window. Confirm with the human rather than silently allowlisting — and note that `EnableLUA=0` is a *machine-wide, reboot-required* change that is rare and loud on a managed host.

**Tuning recommendations:**

1. **Alert on the primary (EID 1); use the corroborator (EID 13) to raise confidence and to backstop patched bypasses.** A `fodhelper`-parented `cmd.exe` at High integrity (primary), preceded seconds earlier by an `ms-settings\shell\open\command` write carrying that same `cmd.exe` in `Details` (corroborator), is irrefutable.
2. **Correlate the two stages by time + account.** The plant (EID 13) and the trigger (EID 1) happen within seconds under the same `acct`. A saved search can join them; even un-joined, an analyst seeing both in a 1-minute window has the whole story.
3. **Weight the *disable* direction.** `EnableLUA /d 0` is the alert; the `/d 1` re-enable is not. The value-anchored regex already does this.
4. **Treat the parent list and hijack-class list as coverage to extend.** Add `slui.exe`, `wsreset.exe`, `dccw.exe`, `sdclt.exe` and any other `autoElevate=true` binaries as you encounter them; add hijack classes (`.cmd`/`.bat` handlers, additional ProgIDs) as new bypasses are published. This is a living list, not a finished one.
5. **Correlate forward — this is a pre-payload signal.** When a bypass fires, immediately pivot forward under the same session for what ran *next* elevated: a service install, a credential dump ([T1003.002](T1003.002-sam-credential-access.md)), a Defender disable ([T1562.001](T1562.001-impair-defenses.md)). The bypass is the door; the payload follows.

## Test Case

The soc-victim install ships 27 T1548.002 atomics. We validate with the **download-free, in-scope** subset (tests 1-8) that exercises both facets and both writer types. **Skip tests 10-21** — these are the **UACME** (10-17) and **WinPwn** (18-21) methods, which download offensive toolkits and will trip Defender, the same reasoning that ruled out the WinPwn/pypykatz tests in [T1082](T1082-system-info-discovery.md) and [T1003.002](T1003.002-sam-credential-access.md). Test **9 (SilentCleanup task)** overlaps [T1053.005](T1053.005-scheduled-task.md) (scheduled-task abuse) and Test **6 (Mocking Trusted Directories)** is a path-spoof variant that "may not work on patched systems" — both optional. Tests **22-27** are further registry UAC-weakening variants (`ConsentPromptBehaviorAdmin`, secure-desktop, WSReset AppX hijack, ProgIDs) — useful **coverage extensions** but not part of the core five; note that **test 23 (WSReset)** hijacks an **AppX** `shell\open\command` key, which the SwiftOnSecurity config *excludes* as noise (`sysmon-config.xml:784`), so its primary EID 1 (`wsreset.exe` parent) would fire but its EID 13 corroborator would be blind — a clean illustration of the "corroborator is a coverage list with gaps" point. The five below are the core.

> **⚠️ Run the bypass tests from a *non-elevated* (medium-integrity) PowerShell** to demonstrate the real escalation. `analyst` is a local admin, so its default token is a split-token medium; a genuine bypass elevates it to High *without a consent prompt*. (Run from an already-elevated shell and the telemetry is identical — `ParentImage=fodhelper`, `Image=cmd`, `High` — but no actual privilege jump occurs, so it is a weaker demonstration.) **Defender real-time protection DOES need to be off** — with RTP on, the first fodhelper run was blocked at launch (`"Access is denied"`) and nothing reached the index; Defender signatures the bypass behavior. Disable it the usual way (Tamper Protection off in the GUI first, then `Set-MpPreference -DisableRealtimeMonitoring $true`), same as the [T1003.002](T1003.002-sam-credential-access.md)/[T1562.001](T1562.001-impair-defenses.md) sessions, and **re-arm afterward**. ### Analyst notes on these real events

- **`ParentImage: …\fodhelper.exe` + `IntegrityLevel: High` — the headline.** The user ran a medium-integrity shell; `fodhelper.exe` auto-elevated (its manifest is `autoElevate=true`), read the hijacked `ms-settings` command, and spawned `cmd.exe` at High — no `consent.exe`, no prompt. The parent is genuine (OS-set), which is why this detection is lab-provable where ART-parent-dependent ones are not.
- **`RuleName: T1042` on the EID 13** — the hijack was caught by the config's generic "Default File Association changes" rule (`\command\`), confirming the pre-flight inference. The tag is *not* UAC-specific: this technique is visible only because a broad shell-hijack rule happens to cover it.
- **`TargetObject: …-1001_Classes\ms-settings\…`** — note the `_Classes` suffix on the SID with no backslash (the HKCU classes redirection), the rendering quirk recorded in Tuning Notes.
- **`Details` names the payload** — `cmd.exe` here, but in a real intrusion this is where the second-stage path/command sits, captured *before* it ever runs elevated.
- **The `control.exe` event is the lesson** — without the live fix, the most realistic of the four bypasses (sdclt, an APT29-emulation payload) would have slipped the primary entirely while looking like a successful escalation only in hindsight. The corroborator caught its `Folder` plant regardless; the primary needed the parent corrected. Two layers, two different failure modes covered.
